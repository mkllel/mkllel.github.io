인프라 · Linux · 서비스 운영

홈랩 기반 백엔드 운영 환경

Proxmox 기반 홈랩에서 개발 및 AI 실험 환경과 상시 운영 환경을 VM 단위로 분리했습니다. 운영 서비스는 Docker Compose로 구성하고 네트워크, DB, 볼륨을 서비스별로 나누어 관리하고 있습니다. 반복적인 서버 점검에는 Read-Only MCP를 연동했습니다.

담당
가상화 구조 설계, Linux VM 구성, Docker 기반 서비스 분리, SSH와 WireGuard를 이용한 원격 관리, Git 기반 배포 및 변경 흐름 구축, Read-Only MCP 설계, 구현 및 운영을 직접 담당했습니다.
기술
Proxmox · Debian Linux · Docker · Docker Compose · Python · MCP · SSH · WireGuard · Git · PostgreSQL
결과
실험용 워크로드와 상시 운영 서비스를 서로 다른 VM으로 분리해 변경이나 장애가 운영 서비스에 미치는 영향을 줄였습니다. 각 운영 서비스의 상태를 독립적으로 확인하고 재시작할 수 있는 환경을 구축했습니다. 반복적인 서버 상태 조회는 Read-Only MCP 기반 도구로 표준화했습니다.

01

문제

개발 실험과 여러 상시 운영 서비스를 한 환경에서 실행하면 높은 자원 사용이나 패키지와 설정 변경이 운영 서비스에 영향을 줄 수 있었습니다.

여러 서비스를 같은 Docker 환경에서 운영하는 만큼 장애가 발생했을 때 영향을 받는 서비스와 데이터의 범위도 명확히 구분할 필요가 있었습니다.

02

설계 및 구성

워크로드의 변경 빈도와 필요한 안정성을 기준으로 Proxmox 위에 역할이 다른 VM을 구성했습니다. 운영 VM에서는 서비스 간 영향을 줄이기 위해 컨테이너와 데이터 영역을 서비스별로 분리했습니다.

  • 개발·AI VM: 개발 도구, 로컬 AI 모델, 실험용 워크로드 실행
  • 운영 VM: Docker 기반 웹 및 자동화 서비스 상시 운영
  • 원격 관리: SSH와 WireGuard를 이용한 서버 관리
  • 변경 관리: Git 저장소를 기준으로 애플리케이션 변경 사항 반영
  • 서비스 분리: 서비스별 Docker Network 구성, DB 및 Volume 분리
  • 상태 관리: healthcheck로 서비스 상태를 확인하고 restart policy로 비정상 종료 시 재시작 기준 설정
  • 장애 확인: 애플리케이션 로그와 컨테이너 로그로 장애 범위 확인
03

운영 및 문제 해결

개발 및 AI 환경의 높은 자원 사용이나 의존성 변경이 상시 운영 서비스에 직접 영향을 주지 않도록 실행 영역을 VM 단위로 분리했습니다.

운영 중 문제가 발생하면 VM 상태 → Docker 컨테이너 상태 → 서비스 로그 → 네트워크 및 DB 상태 순으로 점검하며 원인의 범위를 좁힐 수 있도록 구성했습니다.

AI 기반 운영 조회

반복적인 서버 점검을 위해 Read-Only MCP를 AI 에이전트에 연동했습니다.

  • 자연어 기반 상태 조회: 서비스 상태, 시스템 자원, VM과 LXC 상태를 자연어 요청으로 확인
  • 로그 분석: 최근 오류와 경고를 제한된 범위로 조회하고 AI가 원인 파악에 필요한 내용을 요약
  • 안전한 조회 범위: 허용된 서버와 기능에만 접근하도록 allowlist 적용
  • 민감정보 보호: 로그와 조회 결과의 비밀정보를 마스킹하고 필요한 정보만 AI에 전달
  • 권한 분리: 임의 Shell 실행이나 서비스 중지와 재시작, 파일 및 DB 수정 기능은 MCP에 제공하지 않음

이 조회 도구로 반복적인 서버 상태 확인을 표준화했습니다. 실제 운영 환경에서 자연어 요청에 따른 도구 선택과 서비스 조회를 검증했습니다. 8개의 조회 도구와 51개의 자동 테스트로 조회 범위와 안전 동작도 확인했습니다.

04

결과

실험용 워크로드와 상시 운영 서비스를 서로 다른 VM으로 분리해 변경과 장애의 영향을 제한했습니다.

운영 서비스의 컨테이너와 데이터 영역도 서비스별로 나누어 각 서비스의 상태를 독립적으로 확인하고 재시작할 수 있게 했습니다.

반복적인 상태 조회는 Read-Only MCP로 일관되게 수행하도록 구성했습니다. AI 에이전트가 운영 서버에서 임의 명령을 실행하지 않고도 필요한 상태와 로그를 확인할 수 있도록 했습니다.

현재 여러 서비스를 이 환경에서 상시 운영하며 Linux 서버 관리와 Docker 기반 서비스 운영 경험을 쌓고 있습니다.

05

향후 개선

백업과 복구 절차를 정기적으로 검증하고 서비스 모니터링 및 알림 체계를 고도화할 계획입니다. 실제 운영 데이터를 바탕으로 로컬 LLM과 Read-Only MCP 조합의 활용 범위도 계속 검증할 계획입니다.

다른 경험도 문제와 담당 범위를 기준으로 정리했습니다.
