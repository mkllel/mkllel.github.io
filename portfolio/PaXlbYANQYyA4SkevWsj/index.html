연구용 Python 추론 코드를 웹에서 사용할 수 있도록 FastAPI 기반 서비스 흐름을 구현했습니다. 이미지 업로드부터 모델 실행, 키포인트 후처리, 측정 결과 시각화, 이미지와 CSV 조회 및 다운로드까지 연결했습니다.

담당
AI 모델 개발자가 제공한 모델과 추론 코드를 바탕으로 FastAPI 백엔드 API와 모델 입출력 연동을 구현했습니다. Detectron2 추론 결과의 좌표와 거리 후처리, OpenCV 기반 결과 시각화와 결과 파일 제공 기능도 담당했습니다. SQLite와 bcrypt를 활용해 사용자 등록, 로그인 및 승인 기능을 구현하고 Docker 기반 실행 환경을 구성해 AWS EC2에 배포했습니다. AI 모델 자체는 별도 담당자가 개발했습니다.
기술
Python · FastAPI · Detectron2 · PyTorch · OpenCV · NumPy · pandas · Pillow · SQLite · bcrypt · Docker · AWS EC2 · JavaScript · Git
결과
로컬 파일 기반 추론 코드를 웹 업로드, 분석, 다운로드 흐름에 연결했습니다. 무릎 ACL/PCL 분석에서는 모델이 출력한 6개 키포인트를 거리 측정값과 시각화 이미지로 가공했습니다. 측정값은 웹 화면과 CSV로, 시각화 결과는 조회와 다운로드가 가능한 이미지로 제공했습니다.

  1. X-ray 이미지 업로드
  2. FastAPI에서 이미지 저장
  3. 별도 Python 프로세스로 Detectron2 추론 실행
  4. 키포인트 추출 및 중간 CSV 저장
  5. 좌표와 거리 후처리 및 OpenCV 시각화
  6. 결과 이미지와 거리 측정 CSV 저장
  7. 웹에서 측정값 조회 및 결과 다운로드
02

문제

기존 AI 모델은 로컬 디렉터리의 의료영상을 입력받아 추론 결과 파일을 생성하는 연구 코드 형태로 존재했습니다.

사용자가 웹에서 이용하려면 업로드된 이미지를 추론 코드에 전달하고 모델 출력값을 화면에서 이해할 수 있는 측정 데이터와 결과 이미지로 가공해야 했습니다. 생성된 결과를 조회하고 다운로드할 수 있는 서비스 흐름도 필요했습니다.

  • 모델이 출력한 좌표 데이터를 측정값과 시각화 이미지로 가공

  • 공개 자료에 환자 식별정보가 포함되지 않도록 자료 범위 제한
04

설계 및 구현

AI 추론과 웹 API 연결

FastAPI에서 사용자가 업로드한 이미지를 서버에 저장하고 별도 Python 프로세스로 Detectron2 추론 스크립트를 실행하도록 구성했습니다.

추론이 완료되면 생성된 결과 데이터를 읽어 API 응답으로 반환하고 웹 화면에서 측정값과 분석 이미지를 확인할 수 있도록 연결했습니다.

키포인트 기반 거리 후처리

무릎 ACL/PCL 분석에서는 Detectron2 추론 결과에서 분석에 필요한 6개 키포인트 좌표를 추출했습니다.

NumPy로 키포인트 좌표의 배열과 자료형을 처리하고 Python 연산으로 기준선의 기울기, 교점, 거리를 계산했습니다. 코드에 정의된 43mm 기준 길이를 이용해 픽셀 단위 거리를 mm 단위로 환산했습니다.

OpenCV 결과 시각화

OpenCV로 원본 X-ray 이미지 위에 키포인트 위치, 라벨, 연결선과 계산에 사용되는 기준선을 표시했습니다.

시각화한 결과 이미지를 제공하고 기준 길이로 환산한 거리 측정값은 웹 화면과 CSV로 제공했습니다.

요추 분석에서는 OpenCV로 이미지를 읽고 BGR/RGB 채널 순서를 변환했으며 Detectron2로 시각화한 결과를 Pillow로 저장했습니다.

결과 파일 제공

무릎 분석의 키포인트 좌표를 중간 CSV로 저장하고 후처리한 거리 측정값을 별도 CSV로 생성했습니다.

분석 결과는 이미지와 CSV 파일로 관리했습니다. 웹에서는 측정값과 결과 이미지를 조회하고 결과 이미지와 거리 측정 CSV를 다운로드할 수 있도록 구성했습니다.

사용자 관리 및 실행 환경

SQLite에 사용자 정보와 승인 상태를 저장하고 bcrypt로 비밀번호를 해시하고 검증했습니다. 로그인 시 관리자 승인 여부를 확인하도록 구현했습니다.

Dockerfile에 Python 애플리케이션의 의존성 설치와 Uvicorn 서버 실행 절차를 정의하고 AWS EC2 환경에 서비스를 배포했습니다.

05

회고 및 개선점

현재 구현은 웹 요청이 들어올 때마다 별도 Python 프로세스를 실행하고 추론 모델을 다시 로드하는 방식입니다.

실행 흐름은 단순하지만 요청이 증가하면 모델 반복 로딩에 따른 비용과 공용 입력 및 출력 디렉터리 사용에 따른 파일 충돌 문제가 발생할 수 있습니다.

후속 개선에서는 모델을 메모리에 유지하는 별도 추론 워커와 요청별 작업 디렉터리를 구성할 수 있습니다. 장시간 추론 작업은 작업 큐 기반 비동기 처리로 분리하고 작업 상태 조회 API를 제공하는 방향을 고려하고 있습니다.

회사 프로젝트이므로 소스코드와 운영 주소는 공개하지 않고 담당 범위와 처리 구조를 중심으로 소개합니다.

다른 경험도 문제와 담당 범위를 기준으로 정리했습니다.
